## Package Overview

WildObsR is an R package for accessing, managing, and analyzing camera trap biodiversity data following the **Camera Trap Data Package (Camtrap DP)** standard and **Frictionless Data Package** specifications. It integrates with a WildObs MongoDB backend and provides tools for spatial, temporal, taxonomic, and statistical processing of wildlife observation data.

## Architecture

### Data Flow
1. **Fetch** raw Camtrap DP data via `wildobs_mongo_query()` or `wildobs_dp_download()`. Both functions accept either a MongoDB connection string or HTTP API with API key auth. 
2. **Validate & coerce** with `apply_schema_types()` — enforces Frictionless/Camtrap DP column types including POSIXct datetimes with timezone awareness
3. **Enrich spatially** — assign Australian states, IBRA bioregions, CAPAD protected areas, UTM zones
4. **Process temporally** — resolve overlapping deployments with `update_temporally_overlapping_deployments()`
5. **Generate analysis-ready outputs** — detection/abundance matrices via `matrix_generator()`, formatted for the `unmarked` package

### Key Modules

| File(s) | Responsibility |
|---|---|
| `R/wildobs_mongo_query.R` | Query WildObs MongoDB with spatial/temporal/taxonomic filters; handles API key auth, embargo periods, admin access, data sharing levels |
| `R/wildobs_dp_download.R` | Download complete or partial Camtrap DP packages via HTTP; assigns `CamtrapDP` class |
| `R/apply_schema_types.R` | Validate columns and coerce types to Camtrap DP spec; POSIXct handling with `lutz` for timezone lookup |
| `R/extract_metadata.R` | Extract structured metadata (contributors, licenses, spatial/temporal bounds, geoJSON as `sf` objects) from DP packages |
| `R/spatial_hexagon_generator.R`, `R/resample_covariates_and_observations.R` | Create hexagonal grids and aggregate observations/deployments to custom spatial scales |
| `R/AUS_state_locator.R`, `R/ibra_classification.R` | Assign Australian states and IBRA7 bioregions to coordinates using `sf` and `ozmaps` |
| `R/locationName_buffer_CAPAD.R`, `R/locationName_verification_CAPAD.R` | Protected area assignment using CAPAD shapefile |
| `R/matrix_generator.R` | Generate occupancy/abundance detection history matrices with site- and observation-level covariates |
| `R/survey_and_deployment_generator.R` | Create survey metadata and deployment covariate data frames |
| `R/update_temporally_overlapping_deployments.R` | Identify and resolve temporally overlapping camera deployments |
| `R/utils.R` | Internal helpers: list/df conversion, spatial/temporal emptiness checks, recursive list cleaning, field reformatting for Frictionless spec |

### Included Datasets
- `species_traits` — species home range, body mass, EPBC status (documented in `R/data.R`)
- `ibra` — IBRA7 spatial dataset for bioregion classification

### Data model

The WildObs data model is documented in the `wildobs-data` skill
(`.claude/skills/wildobs-data/`), with per-collection field tables in
`.claude/skills/wildobs-data/reference/`.

**Consult it before** writing or modifying any code that references field names,
joins collections, filters on a controlled vocabulary, or maps between our data
and Camtrap DP. Do not infer field names or semantics from surrounding code —
check the reference file for that collection.

The package targets the [Camtrap DP specification](https://tdwg.github.io/camtrap-dp/)
with WildObs-specific extensions and deviations; the skill's Camtrap DP diff is the
record of those. Core tables are `deployments`, `observations`, and `media`. The
`frictionless` package handles data package resource reading/writing.

**Precedence when sources disagree:** the schema validators in `WildObs_cam-DB`
are authoritative; the skill describes observed reality; the skill was generated
from the PUBLIC mirror (`wildobs_camdb_public`). PROD holds additional unobscured
values but the same fields. If code contradicts the skill, that is a finding to
report, not a discrepancy to silently resolve.

## Working on issues in this repo

- Always work on a new branch named `claude/issue-<n>-<slug>`. Never commit to main. 
  Never open the PR yourself — Zach reviews the branch and opens it.
- Follow `docs/style/zachary_amir_R_coding_style.md` and 
  `docs/style/zachary_amir_R_commenting_style_guide.md` without exception.
- Do not make assumptions beyond what the code and data docs in this repo state.
- Any ambiguity about ecological meaning, data semantics, or default behaviour is 
  Zach's call: post it as a question in an issue comment, don't guess.
  Ambiguity about implementation (naming, structure, helper functions) is yours: 
  pick one and note it.
- End every issue comment with two lists: "Decisions I made" and "Needs your review 
  and testing" — flag anything you couldn't verify.
- Touch only the files needed for the issue.
