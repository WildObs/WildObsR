# WildObs camera-trap database (`wildobs_camdb`)

> ## ⚠️ Measured on the LOCAL mirror, after the 2026-09 camtrap-DP conformance update
>
> Every count, coverage percentage, and vocabulary here was measured on **2026-10-02** against
> the **LOCAL** `wildobs_camdb`, immediately after it was rebuilt to the WildObs profile
> `1.0.2-wildobs.1`. DEV and PROD are updated from LOCAL and should converge on the same
> structure; **PROD may hold additional unobscured or higher-precision values**. Treat
> coverage figures as a floor, and re-measure before concluding a field is unusable in PROD.
>
> **Never print coordinate values** (`latitude`, `longitude`, `spatial` geometry) or records
> for sensitive taxa into logs, reports, or chat. Document the field, not the value.

## Conceptual model

A **project** (`metadata`) is one Camtrap DP data package. It contains many **deployments** —
a single camera at a single location over one continuous time window. Each deployment
produces **media** (images), which are grouped into **observations** (detection events).
Separately, each deployment carries one row of **covariates**: pre-extracted environmental
predictors at five spatial buffer scales.

```
metadata (54 projects)
   │  id ──────────────► projectName  (on every other collection)
   │
   └─ deployments (19,736)
         │  deploymentID ─── 1:1 ──► covariates (19,736)
         │  deploymentID ─── 1:many ─► observations (1,973,401)
         │  deploymentID ─── 1:many ─► media (23,194,220)
         │
         └─ observations ─ observationID ─ 1:many ─► media
                          ─ mediaID ────── 1:1 ───► media (representative file)
```

| Collection | Docs | One document = |
|---|---|---|
| `metadata` | 54 | One project / Camtrap DP data package. |
| `deployments` | 19,736 | One camera at one location for one continuous window. |
| `covariates` | 19,736 | Environmental predictors for one deployment (1:1 with it). |
| `observations` | 1,973,401 | One detection event: a taxon at a deployment in a 5-minute window. |
| `media` | 23,194,220 | One media file (nearly always a single image). |
| `versions` | 1 | Database-level release history — see below. |

Temporal extent: **2009-03-11 → 2026-04-30** (`deploymentStart` min / `deploymentEnd` max).

Per-field tables live in `reference/`:
[`metadata.md`](reference/metadata.md) ·
[`deployments.md`](reference/deployments.md) ·
[`observations.md`](reference/observations.md) ·
[`media.md`](reference/media.md) ·
[`covariates.md`](reference/covariates.md)

### The `versions` collection

One document per environment, recording database releases — **not** WildObsR package versions.

| Field | Type | Meaning |
|---|---|---|
| `environment` | string | `LOCAL` / `DEV` / `PROD`. |
| `currentVersion` | string | Current database version, semver-like (LOCAL: `1.0.1`). |
| `lastModifiedAt` | date | When `currentVersion` last changed. |
| `versions` | array | History: `{version, releasedAt, releasedBy, note}` per release. |

On LOCAL `lastModifiedAt` is 2026-09-03, i.e. it was **not** bumped by the 2026-09 conformance
rebuild. WildObsR does not read this collection; its update notice compares the installed
package against `DESCRIPTION` on GitHub.

## Join keys and cardinality

| From | Key | To | Cardinality | Evidence |
|---|---|---|---|---|
| `metadata.id` | string | `*.projectName` | **1:many** | 54 distinct `id`; 54 distinct `projectName` in deployments and observations. |
| `deployments.deploymentID` | string | `covariates.deploymentID` | **1:1, total** | 19,736 docs each; deploymentID is the primary key of both. |
| `deployments.deploymentID` | string | `observations.deploymentID` | **1:many** | 19,736 distinct in observations — every deployment has observations. Mean ~100 obs/deployment. |
| `deployments.deploymentID` | string | `media.deploymentID` | **1:many** | Mean ~1,175 media/deployment. |
| `observations.observationID` | string | `media.observationID` | **1:many** | Mean ~11.8 media/observation. |
| `observations.mediaID` | string | `media.mediaID` | **1:1 into a subset** | One representative file per observation. |
| `observations.eventID` | string | `observations.observationID` | **1:many** | 1,405,124 events vs 1,973,401 observations; mean 1.40, max 6. |
| `deployments.locationID` | string | `deployments.deploymentID` | **1:many** | 6,614 stations; mean 3.0, max 50 deployments per station. |
| `deployments.locationName` | string | `deployments.locationID` | **1:many** | 153 place names; up to 648 station IDs share one name. |

`deploymentID` is unique in `deployments`, `observationID` is unique in `observations`, and
`mediaID` is unique in `media` — all three are true primary keys. The media-side cardinalities
were not re-scanned on this build, because `media` has
no index on `deploymentID` or `observationID`.

### The temporal hierarchy — the most common modelling mistake

Two nested windows, easy to confuse:

- **`observationID` = a 5-minute window.** The finer grain, and the primary key.
- **`eventID` = a 30-minute window.** The *coarser* grouping. One event holds 1–6 observations.

Count independent detections with `observationID`. Collapse to coarser encounters with
`eventID`. `deltaTime_event` (seconds between consecutive events) supports independence
filtering.

### Query-performance warning

`media` (23.2M docs) is indexed only on `_id`, `mediaID`, and `{projectName, mediaID, _rowHash}`.
There is **no index on `media.deploymentID` or `media.observationID`**, so grouping or joining
media by either scans the whole collection. Always `$match` on `projectName`/`mediaID` first,
or drive the join from the smaller side.

Indexes elsewhere: `observations` on `observationID` and `{projectName, observationID, _rowHash}`;
`deployments` and `covariates` on `deploymentID` and `{projectName, deploymentID, _rowHash}`;
`metadata` on `id`.

## Collection summaries

**`metadata`** — 24 fields + `_id`. One Camtrap DP package per project; `id` is the join key.
The validator now requires 11 fields (see `reference/metadata.md`). Carries two WildObs-only
blocks: `WildObsMetadata` (governance and data sharing) and `versionControlWildObs`.

**`deployments`** — 27 fields. All 24 Camtrap DP deployment fields plus `multiSeason_deploymentGroup`,
`projectName`, `_rowHash`. Sparse hardware fields: `cameraDepth` **0%**, `detectionDistance`
**0.9%**, `cameraHeading` 11.3%. `cameraModel` (57.5%) is free text and unnormalised.

**`observations`** — 31 fields. Detection events. **48.6% are `blank`**; filter to
`observationType == "animal"` for ecological work. 692 distinct `scientificName`. The
individual-level block (`sex`, `behavior`, `individualID`, `individualPosition*`,
`individualSpeed`) is ~0% populated, so distance sampling and REM are not supported here.

**`media`** — 15 fields. Image files. **~98.8% have `filePublic = false`.** `fileMediatype` is
now `image/jpeg` for ~94%, but ~5.5% still carry placeholders such as `image/not_provided`.
Adds two WildObs-only fields: `observationID` and `TIR`.

**`covariates`** — 127 fields. **Entirely WildObs-only; no Camtrap DP equivalent.** One row
per deployment. 18 environmental families × 5 buffer scales, plus 24 GEEBAM fire-severity
class percentages, 3 categorical bioregion fields, and 10 join/context fields.

### Covariate buffer scales

The suffix names the **area** of the buffer, not its radius:

| Suffix | Radius | Area |
|---|---|---|
| `_point` | 1 m | the pixel under the camera |
| `_1km2` | 564.2 m | ~1 km² |
| `_3km2` | 977.2 m | ~3 km² |
| `_5km2` | 1,261.6 m | ~5 km² |
| `_10km2` | 1,784 m | ~10 km² |

Families: `FLII`, `human_footprint`, `altitude`, `ecoregion_intactness`,
`mean_monthly_precipitation`, `mean_monthly_temperature`, `nighttime_lights`,
`human_population_density`, `protected_areas`, `HCAS_static`, `NDVI`,
`terrain_ruggedness_index`, `standardized_precipitation_index`, `HIF`, `EII`,
`GEEBAM_fire_severity_2020`, `days_since_recent_fire`, `fire_events_count`.

Most are 100% populated. Exceptions: `days_since_recent_fire_*` 51–63%, `FLII_*` 75–78%,
`Olson_global_ecoregion` 93.0%.

## Camtrap DP vs WildObs

WildObs is **canonical Camtrap DP 1.0.2 plus a fixed set of additive extensions**, formalised as
the `1.0.2-wildobs.1` profile. Every constraint upstream applies still applies; no standard field
is renamed or retyped. All packages declare `version` and `profile` 1.0.2.

### 1. Camtrap DP fields implemented as specified

**All of them**: 24 deployments fields, 11 media fields, 28 observations fields, and every
package-level property, including `sources` (an **array** of source objects) and `temporal`
(carrying the package-level **`start` / `end`** the standard requires).

### 2. Standard fields used with a WildObs convention

| Field | Camtrap DP says | WildObs does |
|---|---|---|
| `metadata.version` | The package version | Holds the **Camtrap DP standard** version (`1.0.2`). Package versioning lives in `versionControlWildObs`. Documented in the profile. |
| `metadata.created` | ISO 8601 date-time | Stored as a **string** (with offset, e.g. `2025-11-05T16:46:03+10:00`), not a BSON `date`. |
| `observations.mediaID` | "Only applicable for media-based observations" | Populated on **100%** of rows although `observationLevel` is always `event`. Points at a representative file. |
| `observations.observationLevel` | Enum `media` \| `event` | Only **`event`** occurs. |
| `deployments.deploymentGroups` | Free-form grouping | Constrained: one `locationName`, max **100-day** duration. |

### 3. WildObs extensions (all additive)

| Extension | Where | Purpose |
|---|---|---|
| **`covariates` resource (127 fields)** | whole collection | Pre-extracted environmental predictors per deployment at 5 buffer scales. |
| `multiSeason_deploymentGroup` | `deployments` | Parent grouping above `deploymentGroups`; splits continuous sampling at a 30-day gap. |
| `deltaTime_event` | `observations` | Seconds since the previous event at that deployment; independence filtering. |
| `observationID` | `media` | Media → observation link (tdwg/camtrap-dp#377). |
| `TIR` | `media` | Membership in the WildObs Tagged Image Repository. |
| `WildObsMetadata` (10 keys) | `metadata` | Governance and data-sharing block — see below. |
| `versionControlWildObs` | `metadata` | WildObs version of the package. Required. |
| `project.DPID` | `metadata.project` | The package id, repeated on the project block. |
| `contributors[].ROR` | `metadata` | Contributor organisation ROR, for RAiD minting. |
| `taxonomic[].vernacularNamesEnglish` | `metadata` | One English common name string, flattening upstream's language-keyed object. |
| `relatedIdentifierType: "RAiD"` | `metadata.relatedIdentifiers` | Vocabulary addition; 49 entries. |
| `taxonRank` intermediate ranks | `metadata.taxonomic` | `subclass`, `suborder`, `subfamily`, … (observed: subclass 12, suborder 2, subfamily 1). |
| Inline `resources[].schema` object | `metadata.resources` | Declares the extension columns; upstream expects a URL. |
| Per-deploymentGroup `temporal` blocks + `timeZone` | `metadata.temporal` | `{start, end}` per group alongside the package-level extent. |
| `custom` on schema fields | `metadata.resources[covariates].schema.fields[]` | `{spatial: {resolution, buffer_m}, source: {doi, url, citation}}` per covariate. |
| `fileMediatype` `not_provided` | `media` | Placeholder accepted for surveys whose media WildObs does not hold. |
| `projectName`, `_rowHash` | all 4 data collections | Project scoping (joins `metadata.id`) and pipeline change detection. Database machinery, not in the profile's table schemas. |

### Data access, sharing gates, and obscuring machinery

Read from `R/wildobs_mongo_query.R`, `R/wildobs_dp_download.R`, and `resolve_db_access()` in
`R/utils.R`.

**Two access paths, and only one can ever be admin:**

| Path | Argument | Admin? | How decided |
|---|---|---|---|
| Public HTTP API | `api_key` | **Never** | `resolve_db_access()` returns `use_admin = FALSE` for every API call. |
| Direct MongoDB | `db_url` | If the server says so | `resolve_db_access()` runs `connectionStatus`; any role scoped to a database other than `public` grants admin. |

If both are supplied, `db_url` wins. If neither, the function stops.

**Three gates decide whether a non-admin caller gets tabular data** (`is_shareable()` in
`wildobs_dp_download()`):

1. `WildObsMetadata.tabularSharingPreference == "open"`
2. `bibliographicCitation` contains `https://raid.org/` — a **RAiD identifier must be present**
3. `bibliographicCitation` does **not** contain `DEMO`

Fail any one and the project silently downgrades to metadata-only. On LOCAL: **23 `open`,
26 `partial`, 5 `closed`**; all 23 open and all 26 partial citations contain a RAiD, so all
23 open projects pass. `partial` means *metadata visible, tabular data withheld*. Requesting
`closed` without admin is stripped client-side with a `warning()`.

> **Data finding (2026-10-02):** `NSW_Brogo_BCTLandLibraries_2024-25_WildObsID_0049` is
> `open` and its citation ends `RAiD: https://raid.org/10.83062/` — the RAiD prefix with **no
> handle suffix**. It passes gate 2 by substring match. Gate 2 checks for the presence of a
> RAiD URL, not a valid one.

**Embargo is enforced at ingest, not at query time.** Step 6 QAQC
(`WildObs_cam-DB/code_data cleaning/Step6_QAQC/qaqc_tests/08_WildObsMetadata.R`) computes
`created + embargoPeriodMonths` and rewrites `tabularSharingPreference` in place:

| Stored preference | Embargo live? | QAQC action |
|---|---|---|
| `open` | yes | **downgraded to `partial`** |
| `partial` | no (expired) | **upgraded to `open`** |
| `closed` | either | left `closed` |

So `tabularSharingPreference` is a **derived snapshot** ("embargo state as of the last QAQC run"),
expiry is measured from `metadata.created`, and a missing/non-numeric `embargoPeriodMonths`
defaults to a deliberate placeholder of **19 months**.

**EPBC obscuring is NOT implemented.** No taxon-driven obscuring exists in the ingest pipeline
or the query path. EPBC status lives only in `WildObsR::species_traits` as a trait lookup.
**Assume `scientificName` and coordinates are unredacted** and apply your own care.

## Validator vs reality — known disagreements

The validators are authoritative for stated rules. These are the places the database departs
from or exceeds them. (Previously listed issues now fixed and removed: undeclared
`metadata.directory`, `desiredOutputs` object/string mix, `image/JPG` casing, `image/AVI`.)

1. **`media.exifData`** — the validator describes "a valid JSON object" and sets no `bsonType`;
   stored values are **strings** (~0.4% populated).
2. **`observations.mediaID` semantics** — see §2 above.
3. **`required` is weaker than it looks.** MongoDB `required` only means *the key is present*.
   Every covariate also permits `null`, so `FLII_point` is required yet only 75.3% non-null.
   Never infer non-nullness from `required`.
4. **Unused enum values.** `featureType` permits `roadOverpass`, `roadBridge`, `culvert`,
   `carcass`, `fruitingTree` — none occur. `cameraSetupType` `calibration` never occurs;
   `observationType` `unclassified` no longer occurs; `captureMethod` `timeLapse` never occurs
   in a 200k sample.
5. **`fileMediatype` placeholders.** The pattern `^((image|video|audio)/.*|not_provided)$`
   still admits `image/must_confirm_not_provided`, `image/not_provided`,
   `image/files_not_provided` (~5.5% of media combined). The profile's intended placeholder,
   bare `not_provided`, did not appear in a 200k sample.
6. **Covariate field metadata is damaged.** In `metadata.resources[covariates].schema.fields`:
   - descriptions still open with "calculated with a meter buffer" (number missing) before
     appending the correct radius;
   - **`custom.spatial.buffer_m` is misaligned on the GEEBAM fields**: the five
     `GEEBAM_fire_severity_{0..4}_percent_1km2` fields carry `1, 564.2, 977.2, 1261.6, 1784`
     (the five-scale cycle) and every later GEEBAM percent field carries an empty object;
     `IBRAsubRegionName` has the string `"1"` and `IBRAbioRegionName` an empty object.
   The scale is carried reliably by the field-name suffix, not by `custom` or the prose.

## Practical query notes

- **Always filter `observationType`.** 48.6% of observations are `blank`.
- **Scope by `projectName` early.** It is the leading key of the compound index on all four
  data collections.
- **`$sample`, never `find(limit=n)`,** for exploration — insertion order is grouped by project.
- **Dates are BSON `date`** in `deployments`, `observations`, `media` — but `metadata.created`
  and every `metadata.temporal` value are **strings** (`YYYY-MM-DD`). Do not mix them.
- **Read-only.** This skill documents the database; do not write, update, or drop anything.
